# Зачем нужны этапы

## Этап 1. Проверить и зафиксировать Ruby/Rails

### Зачем

Фиксация версий делает окружение воспроизводимым: приложение разрабатывается, тестируется и запускается на одинаковых версиях Ruby и Rails. Это уменьшает риск различий в API, генераторах и зависимостях на разных машинах.

## Этап 2. Создать Rails-приложение

### Зачем

Генератор создаёт стандартный каркас Rails с согласованными SQLite, Importmap, Turbo, Stimulus, Propshaft и сборкой Bootstrap SCSS. Такой старт сохраняет принятые соглашения Rails и не требует вручную собирать базовую структуру приложения.

## Этап 3. Инициализировать Git и сделать начальный коммит

### Зачем

Начальный коммит создаёт проверенную базовую точку истории до функциональных изменений. Благодаря этому последующие этапы можно просматривать отдельно, сравнивать с исходным каркасом и при необходимости разбирать причину изменений.

## Этап 4. Перевести шаблоны на Slim

### Зачем

Единый формат представлений делает разметку последовательной и уменьшает визуальный шум HTML. Подключение Slim до создания прикладных страниц исключает дальнейшее смешивание ERB и Slim и задаёт единый подход для всех новых шаблонов.

## Этап 5. Настроить Bootstrap, SCSS и Simple Form

### Зачем

Bootstrap и SCSS создают единую адаптивную визуальную основу приложения, а Simple Form формирует согласованную разметку полей, ошибок и подсказок. Настройка этих инструментов до создания прикладных форм предотвращает дублирование разметки и обеспечивает одинаковое поведение интерфейса.

# Вопросы и ответы

## Что такое `config/initializers/assets.rb`?

Initializer — это Ruby-файл, который Rails выполняет при загрузке приложения после основной конфигурации фреймворка и подключённых гемов. Initializers используют для однократной настройки компонентов приложения. Изменения в них обычно требуют перезапуска Rails-сервера.

`config/initializers/assets.rb` настраивает работу с ассетами — CSS, JavaScript, шрифтами и изображениями. В текущем проекте он выполняет три задачи:

- устанавливает версию ассетов `Rails.application.config.assets.version`; изменение версии позволяет принудительно обновить адреса ассетов и сбросить старый браузерный кеш;
- добавляет каталог шрифтов Bootstrap Icons из `node_modules` в пути поиска ассетов;
- добавляет каталог JavaScript Bootstrap в пути поиска и указывает подготовить `bootstrap.bundle.min.js` для использования через Importmap.

SCSS собирается отдельно командой `yarn build:css`: исходный `application.bootstrap.scss` преобразуется в `app/assets/builds/application.css`. После этого Propshaft предоставляет собранный CSS и остальные доступные ассеты браузеру. Сам initializer не компилирует SCSS и не выполняется при каждом HTTP-запросе.

## Что вообще такое assets?

Assets — это статические ресурсы, которые браузер загружает вместе с HTML-страницей. Они не являются данными предметной области и обычно не формируются заново для каждого HTTP-запроса.

К assets относятся:

- CSS — инструкции внешнего вида элементов: цвета, размеры, отступы и адаптивная раскладка;
- JavaScript — поведение и интерактивность элементов;
- изображения и иконки;
- шрифты;
- иногда другие статические файлы, необходимые интерфейсу.

Поэтому понимание assets как «инструкций отображения элементов» частично верно именно для CSS, но понятие assets шире. У разных частей страницы разные обязанности:

- HTML, создаваемый Rails views, задаёт структуру и содержимое страницы;
- CSS описывает, как эта структура выглядит;
- JavaScript описывает интерактивное поведение;
- изображения, иконки и шрифты являются используемыми визуальными ресурсами.

В проекте есть исходные и готовые assets. Например, `application.bootstrap.scss` — исходный SCSS. Команда `yarn build:css` преобразует его в готовый `application.css`, понятный браузеру. Propshaft находит готовые файлы, формирует для production адреса с цифровыми отпечатками и отдаёт их браузеру.

Цифровой отпечаток добавляется к имени файла, например `application-a1b2c3.css`. Когда содержимое меняется, меняется и адрес. Благодаря этому браузер может долго хранить старые assets в кеше, но после обновления приложения гарантированно загрузит новую версию.

## Что такое `vertical_form`?

`vertical_form` — это именованный wrapper Simple Form. Wrapper представляет собой рецепт HTML-разметки одного поля: в каком порядке вывести label, input, hint и сообщение об ошибке, какими элементами их обернуть и какие CSS-классы добавить.

В `config/initializers/simple_form_bootstrap.rb` wrapper `vertical_form` настроен для обычной вертикальной Bootstrap-формы: подпись располагается над полем, а следом выводятся подсказка и ошибка. Он назначен как `default_wrapper`, поэтому применяется автоматически, если конкретная форма или поле не выбрали другой wrapper.

Simple Form также содержит отдельные wrappers для checkbox, radio button, select, file input, горизонтальных и inline-форм. Это необходимо, потому что этим типам полей нужна разная Bootstrap-разметка.

## Что такое `is-invalid`?

`is-invalid` — стандартный CSS-класс Bootstrap для поля с ошибкой валидации. Он визуально отмечает поле как некорректное, обычно красной рамкой и соответствующими цветами.

Simple Form добавляет этот класс к input, когда связанный объект модели содержит ошибку для данного атрибута. Класс только отображает состояние: он не проверяет данные и не заменяет Rails validations в модели.

## Что такое `invalid-feedback`?

`invalid-feedback` — класс Bootstrap для текста, объясняющего ошибку поля. Например, под полем может появиться сообщение «не может быть пустым».

Обычно `invalid-feedback` используется рядом с элементом, имеющим класс `is-invalid`. Bootstrap связывает эти классы визуально: `is-invalid` выделяет поле, а `invalid-feedback` оформляет и показывает текст ошибки. Сам текст формирует Rails/Simple Form на основе ошибок модели.

## Что такое `form-check`?

`form-check` — Bootstrap-класс контейнера для checkbox и radio button. Внутри него обычно находятся:

- элемент выбора с классом `form-check-input`;
- связанная подпись с классом `form-check-label`.

Такая структура обеспечивает правильные отступы, выравнивание и область нажатия. Для переключателя Bootstrap дополнительно использует `form-switch`, а для размещения нескольких вариантов в одной строке — `form-check-inline`.
