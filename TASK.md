Тестовое задание:
Написать на Ruby on Rails 5/6, Ruby 2.5+ приложение "Справочник сотрудников организации":
1. Система содержит реестр сотрудников организации со следующим набором данных:
1.1 фамилия (текст, обязательно),
1.2 имя (текст, обязательно),
1.3 отчество (текст),
1.4 должность (справочник, обязательно),
1.5 дата приема на работу (дата, обязательно),
1.6 телефон (текст),
1.7 email (текст),
1.8 логин (текст, обязательно),
1.9 пароль (обязательно).
2. В системе имеется справочник должностей, содержит название должности (текст). Заполнен набором данных:
должность 1, должность 2, должность 3.
3. В системе сотрудники являются ее же пользователями (аутентификация через поля логин и пароль, gem devise), регистрации пользователей нет, создаются вручную. Доступ в систему без аутентификации запрещен.
4. В системе предусмотрены следующие роли пользователей (gem rolify или иной) - администратор и сотрудник.
5. Авторизация действий пользователей - gem cancancan, либо pundit.
6. Администратор может просматривать реестр сотрудников, создавать новых сотрудников, устанавливать/изменять любую информацию о сотруднике (включая установку роли, логина и пароля), удалять сотрудников.
7. Сотрудник может просматривать реестр сотрудников, НЕ видит информации о ролях, логинах и паролях. Может редактировать свою карточку, а именно:
изменять пароль, телефон и email.
8. Всем пользователям доступна выгрузка реестра сотрудников в виде Excel файла, со следующим составом данных: ФИО, должность, телефон, email.
9. БД системы - любая SQL, допустима sqlite3.
10. UI - Bootstrap 4
11. JS - особых требований нет, допустимы любые библиотеки, включая jQuery. CoffeeScript допустИм.
12. Первично в системе создается пользователь-администратор с логином и паролем admin.
Дополнительные требования (не обязательно, но их выполнение будет плюсом):
1. Шаблонизация представлений (views) на slim; 2. CSS - SCSS; 3. Сборка ассетов через webpack; 4. Использование rails-ujs; 5. Использование stimulusjs; 6. Использование turbolinks; 7. (При необходимости) использование компонент (gem view_component или komponent); 8. (При необходимости) использование гемов из набора dry-rb; 9. Использование simple_form; 10. Оформить проект системы в виде git-репозитория (допустимо представить в виде рабочей копии, не обязательно выкладывать); 11. Добавить Docker-контейнер (Dockerfile + docker-compose.yml). 12. Сделать страницу "аналитики" для администратора - вывести все должности и по 5 последних (по дате приема) сотрудников в каждой.
