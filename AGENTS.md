# Инструкции для OpenCode

Перед изменением проекта прочитай:

- `TASK.md` — первоначальное задание заказчика;
- `docs/IMPLEMENTATION_SPEC.md` — согласованные изменения, архитектура и технические решения;
- `docs/PROGRESS.md` — текущее фактическое состояние реализации.

`TASK.md` является историческим исходным заданием. Не изменяй этот файл без прямого указания пользователя.

Если документы расходятся:

- требования из `TASK.md` применяются как базовые;
- явно изменённые или дополненные требования из `docs/IMPLEMENTATION_SPEC.md` имеют приоритет над соответствующими пунктами `TASK.md`;
- версии, архитектура, библиотеки и порядок реализации всегда берутся из `docs/IMPLEMENTATION_SPEC.md`;
- `docs/PROGRESS.md` описывает только текущее состояние и не может изменять требования.

`AGENTS.md` определяет только порядок работы с проектом. Не используй его для хранения функциональных или технических требований приложения.

Все согласованные изменения исходного задания должны быть зафиксированы в `docs/IMPLEMENTATION_SPEC.md`.

Не меняй согласованный стек и не добавляй зависимости без обсуждения.

JavaScript, Dockerfile, Docker Compose, Rails associations, Devise, Rolify и Pundit объясняй подробно.

Не выполняй разрушительные Git-команды.

Не добавляй секреты, `config/master.key`, `.env` и рабочие SQLite-файлы в Git.

## Порядок реализации

Дорожная карта проекта находится в разделе 21 файла `docs/IMPLEMENTATION_SPEC.md`.

Остальные разделы спецификации содержат требования, ограничения и критерии готовности отдельных этапов.

Работай только над одним крупным этапом одновременно.

В начале работы:

1. Прочитай `TASK.md`.
2. Прочитай `docs/IMPLEMENTATION_SPEC.md`.
3. Прочитай `docs/PROGRESS.md`.
4. Найди первый незавершённый этап из раздела 21 спецификации.

Перед началом каждого крупного этапа:

1. Назови номер и название этапа.
2. Объясни, что собираешься сделать и зачем.
3. Объясни, как будет проверен результат.
4. Дождись подтверждения пользователя.

После подтверждения:

1. Выполни только согласованный этап.
2. Не начинай следующий этап автоматически.
3. Запусти относящиеся к этапу тесты и проверки.
4. Покажи результат выполненных проверок.
5. Перечисли созданные и изменённые файлы.
6. Обнови `docs/PROGRESS.md`.
7. Добавь в `docs/LEARNING_NOTES.md` только номер, название завершённого этапа и объяснение, зачем этот этап нужен.
8. Остановись и дождись подтверждения пользователя.

Если команда или тест завершились ошибкой:

1. Не отмечай этап завершённым.
2. Объясни причину ошибки.
3. Предложи исправление.
4. Не меняй стек и архитектуру без подтверждения пользователя.

Не изменяй порядок этапов без согласования.

После завершённого этапа предложи сообщение для тематического Git-коммита. Не выполняй `git commit` без подтверждения пользователя.

## Сохранение прогресса

В начале каждой новой сессии прочитай `docs/PROGRESS.md`.

После завершения и проверки каждого крупного этапа обновляй `docs/PROGRESS.md`.

Файл должен содержать только актуальное состояние:

- завершённые этапы;
- текущий этап;
- основные изменённые файлы;
- выполненные проверки и их результат;
- важные принятые решения;
- предупреждения;
- текущие блокеры;
- следующий шаг.

Не копируй в него:

- полный вывод терминала;
- большие фрагменты кода;
- содержание переписки;
- подробное описание каждого небольшого действия.

Не отмечай этап завершённым, пока относящиеся к нему проверки не прошли успешно.
